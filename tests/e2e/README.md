## v0.1 真实监控链路

```text
启动锁定版本的 Online Boutique 与监控栈
  → 运行购物流量，验证健康与样本量
  → 注入有 TTL 的 Redis 不可用故障，不发布新镜像
  → 真实 Alertmanager 通知到 Gateway
  → Agent 自动消费事件并创建唯一调查
  → 经 HTTP 收集业务、日志和资源证据
  → 生成根因结论及人工建议
  → 独立操作者按运行手册恢复并记录结果
  → Gateway 用新的业务窗口验证恢复
  → 汇总报告、外部评分与清理结果
```

Agent 的真实输入来自 Gateway，不能直接读取平台 fixture 或场景答案。人工 CLI 触发只适用于调试/重放，不替代 live 告警验收。

## 运行层次

| 层次 | 数据与模型 | 证明什么 |
|---|---|---|
| fixture 回归 | HTTP fixture + 确定性替身 | 契约、失败语义、恶意输入与调查流程 |
| live 回归 | 真实应用/遥测 + 确定性替身 | 告警、集成、恢复与环境可重复性 |
| live LLM | 同一真实 Gateway + 真实模型 | 模型在真实证据上的有界调查，不等于统计泛化结论 |

三类结果分别标注，使用同一引擎和验证规则。精确重复次数与通过条件以 [共同路线图](../../docs/PROJECT_DIRECTION_AND_CHECKPOINTS.md) 的首版验证矩阵为准；测试命令随实现提交。

## 必需断言

- 无 baseline/candidate、Git diff 或新发布仍能完成调查。
- 重复/乱序告警不创建同事故的多个活动调查；后续新故障产生新事故。
- 根因证据有独立来源及依赖依据，不把症状服务直接当作根因。
- 遥测缺失、低样本、过期和冲突不被解释为正常或恢复。
- 未注册工具、scope 越界及恶意日志不能绕过权限。
- 人工操作成功、Pod Ready、告警 resolved 均不能跳过真实业务验证。
- TTL 自动清理与人工恢复分别归因；注入/清理失败记录为环境失败。
- 连续运行可清理重建，原始时间、来源、模型与上游版本可追溯。
